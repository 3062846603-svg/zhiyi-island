# 运行与部署指南

本指南用于重新搭建环境，不包含作者个人电脑或服务器的连接信息。数据库、Redis 和 MinIO 需要另行安装；本仓库没有提供从空白系统开始的一键安装器。

## 1. 准备依赖

- Java 17 或兼容版本；后端提供 Maven Wrapper。
- Node.js 20.19.x 或 Node.js 22.12 及以上（以 package.json engines 为准）。
- PostgreSQL（部署验证使用 16）及 pgvector 扩展。
- Redis、MinIO。

默认连接为 PostgreSQL localhost:5432、Redis localhost:6379、MinIO localhost:9005。若实际端口不同，修改后端配置。不要把数据库或缓存端口直接开放到公网。

## 2. 初始化空数据库

先创建 `zhiyi_island` 数据库，安装 pgvector 后，在新建的空数据库中执行：

```sh
psql -U postgres -d zhiyi_island -f zhiyi-island-backend/src/main/resources/db/init.sql
```

此脚本用于初始化，不是已有数据库的版本迁移工具。修改已有数据库前先备份。

## 3. 配置后端

将 `zhiyi-island-backend/src/main/resources/application-local.yml.example` 复制为同目录的 `application-local.yml`，填写自己的数据库密码、MinIO 凭据及随机 JWT 密钥。该文件已被 Git 忽略。

数据库用户名、端口和 Redis 密码可通过主配置中对应的环境变量设置，例如 `DB_USERNAME`、`DB_URL`、`REDIS_PASSWORD`。不要在公开的 application.yml 中填写真实凭据。

邮件功能需填写自己的 `spring.mail.username` 和 `spring.mail.password`；后者是 SMTP 授权码。未配置时，验证码邮件不能正常发送。

如需 DeepSeek，将本地配置中 `spring.ai.siliconflow` 对应的小节替换为以下内容（历史配置名保留 siliconflow）：

```yaml
spring:
  ai:
    siliconflow:
      provider: deepseek
      base-url: https://api.deepseek.com
      api-key: ${DEEPSEEK_API_KEY:}
      model: ${DEEPSEEK_MODEL}
      knowledge-model: ${DEEPSEEK_MODEL}
      thinking-enabled: false
      embedding-enabled: false
app:
  ai:
    auto-extract-knowledge: false
```

将这些字段合并到已有的 `spring` 节点，不要重复定义 YAML 顶层键。自行在启动环境设置 `DEEPSEEK_API_KEY` 和账号可用的 `DEEPSEEK_MODEL`。关闭自动知识提取后，手动调用 AI 的操作仍会向所配置服务商发送相应文本。

本项目打包排除了本地配置，因此启动时显式加载该文件。在后端目录执行：

```sh
./mvnw spring-boot:run -Dspring-boot.run.arguments="--spring.config.additional-location=file:./src/main/resources/application-local.yml"
```

Windows PowerShell 将 `./mvnw` 换为 `./mvnw.cmd`，并把整个 `-Dspring-boot.run.arguments=...` 参数放入引号。后端默认端口为 8080。

## 4. 启动前端

另开终端，进入前端目录：

```sh
npm ci
npm run dev
```

打开终端输出的本地地址，默认端口为 5174。Vite 将 `/api` 转发到本机后端 8080。

## 5. 服务器部署参考

- 前端执行 `npm run build`，上传生成的 dist 内容；生产环境 API 地址使用 `/api`。
- 后端执行 `./mvnw clean package`，上传生成的应用 JAR。
- [deploy/ecs](../deploy/ecs/) 提供 Nginx、systemd、资源限制、日志及备份模板。路径、服务名和依赖须按实际环境调整。
- `prepare-server.sh` 假设相关软件已经安装，并使用 `/root/zhiyi-install` 作为安装文件目录；阅读脚本后再使用，不适合直接运行在已有业务和数据的服务器上。
- 将数据库、Redis、MinIO 和 AI/邮件凭据放在服务器专用配置文件，限制读取权限。不要放入前端代码、Git 或公开下载目录。
- 模板优先用于通过 SSH 隧道访问的私有预览；上线前处理审查报告中的问题，再配置域名、HTTPS 和公网访问。
- 定时备份模板保存于同一台服务器，仍需另行安排异地备份并验证恢复。

个人操作脚本和带个人环境信息的文档未包含在此公开版本中。
